# Tagging and Naming

## File names
- Notes: `Title Case With Spaces` or `Short-Hyphenated`, unique across the vault.
- Daily: `YYYY-MM-DD`.
- Projects: `Project - <name>`; meetings: `YYYY-MM-DD Meeting - <topic>`; leads: `Lead - <company>`.
- Prompts: `Prompt - <purpose>`; decisions: `Decision - <topic>`.
- Attachments: `YYYY-MM-DD_short-description.ext`.
- Avoid characters `\ / : * ? " < > |` and `# ^ [ ]`.

## Tag taxonomy
Keep it small. Prefer properties (`type`, `status`) over tags for state.

| Tag | Meaning |
|---|---|
| `#sales`, `#sales/lead`, `#sales/research` | sales work |
| `#ai`, `#prompt`, `#agent`, `#automation` | AI workflows |
| `#security` | security threats, audits and controls |
| `#decision` | recorded decisions (from the Decision template) |
| `#meta` | vault documentation |
| `#moc` | maps of content / hubs |
| `#idea`, `#todo`, `#review` | transient markers; remove once handled |

## Status values
`draft` > `active` > `waiting` > `done` > `archived`
